# Taskflow Local — October 5 desktop update

An offline Windows task timeline with local language and screenshot input. Manual tasks work without a model; model-proposed changes require approval.

**This release contains changes made after the October 5, 2026, 06:59 UTC challenge deadline.** The original `v0.1.0` tag and release assets remain unchanged. See the README's dated disclosure for the scope and timing of every update.

## Downloads

- **Taskflow-Local-2026-10-05-windows-x64-setup.exe** — recommended Windows x64 installer. Includes the app, pinned llama.cpp runtime, DLLs and notices. Use this build for Windows notifications, which need installed Start Menu registration.
- **Taskflow-Local-2026-10-05-windows-x64-portable.zip** — extract the whole folder and run `taskflow-local.exe`. Keep `runtime/llama/` beside it. Use the installer for notification support.
- **SHA256SUMS.txt** — SHA-256 checksums for both downloads.

Requires Windows x64 and Microsoft Edge WebView2. This unsigned build may trigger SmartScreen. Quit an older Taskflow instance from its tray menu before installing. Tasks and downloaded models live in separate user-data directories and are preserved by an ordinary upgrade.

The application version metadata remains `0.1.0`. The dated tag **`desktop-update-2026-10-05`** distinguishes this build from the original release; no dependency or toolchain versions were changed for this update.

## Changes

- Original Taskflow checkmark artwork in the header, favicon, Windows app and tray icons.
- Eleven colour schemes with selectable palette previews: Classic, Slate, Nord, Dracula, Solarized, Cyberpunk, Dark Grey, Full Black, Forest, Bubblegum and Autumn. Forest and Autumn now have dark backgrounds.
- Compact task controls, clearer borders and focus indicators, sticky filters, native dark controls, and a pinned request box with independently scrolling results.
- A saved **Chat** on/off switch. Off hides the composer, discards unsaved chat proposals, and unloads a loaded model. Manual task controls and reminders stay available. It waits for requests/saves to finish; on focuses the input without starting the model. An unload failure is reported without preventing chat from being hidden.
- **Settings → Test notification**, using the same native notification plugin as reminders.
- **Custom date and time** for desktop reminders, in addition to the preset intervals. It must be in the future and at/before the task time. Rescheduling keeps the same lead time unless you explicitly edit the reminder. An unchanged reminder is read from current SQLite state, so editing a title does not re-arm a fired reminder.
- Clipboard screenshot input and the earlier scrolling fixes, which were committed before the deadline but were absent from the original binary assets.

## Model setup

Model weights and the image projector are **not included**. Manual controls work immediately. Use **Settings → Open Models Folder**, copy the files described in the [README](https://github.com/S-Srinivasan-06/hacktoberfest-weekend-2026-10-01/tree/desktop-update-2026-10-05#model-file-placement), then refresh models. The pinned filenames are `gemma-4-E2B_q4_0-it.gguf` and optional matching `gemma-4-E2B-it-mmproj.gguf`.

Optional Ollama models must already be downloaded locally. Taskflow does not install Ollama or download models. A screenshot yields one validated proposal, not bulk extraction or persisted image chat.

## Evidence and limits

TypeScript checking, all 32 existing unit tests, Rust checking, release compilation and NSIS packaging passed. Mocked browser checks covered dark themes, small-window scrolling, chat request guards, approval before writes, model unloading, preference restoration and manual controls with chat off. A custom-reminder walkthrough checked invalid-time rejection, exact-time restoration, title editing, rescheduling and an explicit reminder-time change.

The installer was applied to the existing Windows installation. The installed executable matched the build after accounting for Tauri's three-byte NSIS marker, and current frontend assets were present. The database hash was unchanged across installation. All 32 runtime files/notices matched the build. The app launched without starting the model.

Windows reported notifications enabled for Taskflow's registered identity and accepted a diagnostic toast during troubleshooting. **Actual notification-banner visibility, clean-account installation, tray interactions and installed-UI model/persistence flows still need acceptance checks.** Mocked browser behavior and compilation do not verify those native flows. The earlier real Gemma model checks were not rerun for this UI update.
